# ТЕМП

Сайт магазина спортивной одежды на ASP.NET Core Blazor. Основная работа сосредоточена на главной странице: композиция из товаров вместо слайдера, закреплённая навигация, подборки одежды и большой фотофуттер с появлением при прокрутке.

![Главная страница](docs/home.png)

## Стек

- C# и .NET 10, Blazor Interactive Server.
- HeroUI Styles и Tailwind CSS 4, интерактивные компоненты на Razor.
- Локальные шрифты Unbounded и Inter с кириллицей.
- PostgreSQL через Npgsql, один GET `/api/catalog` для витрины.

## Запуск

Установите .NET SDK 10 и Docker с Compose. Для пересборки стилей также нужны Node.js и pnpm.

Локальная база запускается отдельным контейнером PostgreSQL 17. Команды для PowerShell:

```powershell
docker compose up -d --wait
$env:DATABASE_URL = "postgresql://tempstore:tempstore_dev@127.0.0.1:5438/tempstore?sslmode=disable"
pnpm install --frozen-lockfile
pnpm run build:css
dotnet restore TempStore.slnx
dotnet run --project src/TempStore
```

Сайт откроется по адресу http://localhost:5186. Готовый CSS включён в репозиторий: если стили не меняются, команды `pnpm` можно пропустить. `compose.yaml` публикует БД только на `127.0.0.1:5438` и хранит данные в томе `postgres_data`. Логин и пароль из этого файла предназначены только для локальной разработки.

Приложение требует `DATABASE_URL`; без неё запуск завершается понятной ошибкой. Поддерживаются адреса `postgres://` и `postgresql://`, а также обычная строка подключения Npgsql. В адресе можно указать `sslmode=disable`, `allow`, `prefer`, `require`, `verify-ca` или `verify-full`; дополнительные параметры задавайте через формат Npgsql. Спецсимволы в логине, пароле и имени БД нужно URL-кодировать.

Локальную настройку можно сохранить вне репозитория вместо переменной окружения:

```powershell
dotnet user-secrets set "DATABASE_URL" "postgresql://tempstore:tempstore_dev@127.0.0.1:5438/tempstore?sslmode=disable" --project src/TempStore
```

При работе со стилями:

```sh
pnpm run watch:css
```

После изменения стилей пересоберите приложение, чтобы обновились отпечатки статических ресурсов.

## Проверки

```powershell
$env:TEST_DATABASE_URL = "postgresql://tempstore:tempstore_dev@127.0.0.1:5438/tempstore?sslmode=disable"
dotnet build TempStore.slnx
dotnet run --project tests/TempStore.Checks
```

Проверки требуют `TEST_DATABASE_URL` с локальным адресом (`localhost`, `127.0.0.1` или `::1`). Они создают три временные схемы с уникальными именами, работают только в них и удаляют их после завершения. Учётной записи нужны права на создание схемы. Проверки не запускаются в рабочей схеме приложения.

## Форматирование

```sh
pnpm run format
pnpm run format:check
dotnet format whitespace TempStore.slnx
dotnet format whitespace TempStore.slnx --verify-no-changes
```

Prettier форматирует JavaScript, исходный CSS, JSON, YAML и Markdown. C# форматируется через `dotnet format`, Razor — встроенным форматтером C#/Razor в редакторе. Общие отступы заданы в `.editorconfig`: 4 пробела для C#/Razor, 2 для остальных файлов. Сгенерированный `wwwroot/app.css` и lock-файл не форматируются.

## Админка

Страница `/admin` позволяет добавлять, изменять и удалять товары, просматривать заказы и менять их статусы. Изображение выбирается из файлов `wwwroot/images/products`; загрузки новых файлов через сайт нет. При удалении товара удаляются и его отзывы, состав ранее оформленных заказов сохраняется.

Для входа задайте пароль в переменной окружения `Admin__Password` перед запуском приложения. На хостинге добавьте её в переменные проекта. Пароль в репозиторий не добавляется; без настройки вход закрыт. После изменения пароля перезапустите приложение.

Для локальной разработки пароль также можно сохранить вне репозитория:

```sh
dotnet user-secrets set "Admin:Password" "ваш-пароль" --project src/TempStore
```

Сессия администратора хранится в защищённой cookie и действует до 8 часов или перезапуска приложения. Пароль проверяется через хеш, запросы на изменение защищены antiforgery-токеном, число попыток входа ограничено. На сервере нужен HTTPS.

## Хостинг и автообновление

Проект размещён на [Relaxdev](https://relaxdev.ru/projects/temp-store). В корне репозитория есть `Dockerfile`: он собирает CSS и публикует приложение на .NET 10. В настройках проекта должны быть указаны репозиторий `catoo-hub/temp-store`, ветка `main`, корень репозитория и сборка через `Dockerfile`. Приложение слушает порт `10000`.

Автодеплой настраивается в Git-интеграции Relaxdev. Для создания webhook подключённому аккаунту GitHub нужны права администратора репозитория; GitHub Actions для этого проекта не используется.

В переменных проекта задайте `DATABASE_URL` внешней PostgreSQL и `Admin__Password`. Используйте выданные хостингом параметры SSL; локальные реквизиты из `compose.yaml` для сервера не подходят. Строку подключения не добавляйте в репозиторий. Данные каталога, аккаунтов и заказов хранятся в PostgreSQL и сохраняются при пересоздании контейнера приложения. Для постоянного входа между деплоями ключи ASP.NET Core Data Protection тоже должны храниться на постоянном томе; без этого пользователю потребуется войти снова.

Приложение работает только с PostgreSQL. Старые файлы SQLite не изменяются и автоматически не переносятся; настройка `Database__Path` больше не используется. Если в SQLite есть нужные данные, их перенос выполняется отдельно.

## Состояние проекта

Главная страница адаптирована для компьютеров и телефонов. Каталог, карточки товаров, бренды и отзывы получают данные через API. Поиск, сортировка и фильтры работают в клиентской витрине; корзина сохраняется в localStorage.

Схема таблиц PostgreSQL создаётся при первом запуске; саму БД нужно создать заранее или запустить через Compose. Начальные данные каталога (8 товаров, 2 бренда, 3 отзыва) находятся в `src/TempStore/Data/catalog.sql` и добавляются один раз. Повторный запуск сохраняет изменения и не восстанавливает удалённые товары. Цены хранятся целым числом копеек, ID удалённых товаров не используются повторно.

Браузер запрашивает `/api/catalog`, а `CatalogService` хранит полученный снимок до перезагрузки страницы. При ошибке загрузки появляется кнопка повторной попытки; сохранённая корзина остаётся нетронутой. Для небольшого каталога это позволяет обойтись без отдельных контроллеров, репозиториев и серверной пагинации.

Вход администратора и управление товарами работают через `/api/admin`. Регистрация, вход и редактирование имени и телефона покупателя — через `/api/account`; пользователи сохраняются в таблице `Users`, пароли — только в виде хешей. Личный кабинет находится на `/account`.

Оформление заказа доступно после входа. Покупатель указывает получателя, телефон и адрес; доставка бесплатная. Сервер проверяет товары и размеры, рассчитывает сумму по текущим ценам и сохраняет состав заказа в `Orders` и `OrderItems`. Повторная отправка того же заказа не создаёт дубль. Корзина очищается после подтверждения сохранения сервером.

В личном кабинете видны только свои заказы, их состав, сумма и статус. Кнопка тестовой оплаты переводит заказ в оплаченный без списания денег и ввода реквизитов карты. Реальная платёжная система не подключена. Неоплаченный заказ можно оплатить позже из истории; повторное нажатие безопасно.

В админке оплаченный заказ проходит статусы «Новый» → «В обработке» → «Отправлен» → «Завершён». До отправки его можно отменить. Заказ с тестовой оплатой не требует возврата денег. Отправка обратной связи пока не реализована; начальные товары и отзывы тестовые.

## Структура

- `src/TempStore/Components` — страницы, layout и компоненты.
- `src/TempStore/Styles` — исходные стили.
- `src/TempStore/Services` — каталог, корзина и уведомления.
- `src/TempStore/Data` — работа с PostgreSQL и начальное заполнение.
- `src/TempStore/wwwroot` — изображения, шрифты, JavaScript и собранный CSS.
- `tests/TempStore.Checks` — проверки каталога, корзины, аккаунтов и заказов.

Источники фотографий товаров указаны в `src/TempStore/wwwroot/images/products/sources.json`. Лицензии шрифтов находятся рядом с файлами шрифтов в `src/TempStore/wwwroot/fonts`.
